Собственные разработки

1 · Правила реестра

Продукты — собственность компании. Разработку ведёт руководитель отдела доставки лично; вклад труда учитывается в реестре вкладов партнёрства (документ 5). Все репозитории, деплои, домены и ключи — только на аккаунтах компании.
Под себя → на рынок. Один код, два инстанса. Каждый продукт строится сразу мультитенантно, но живёт двумя развёртываниями: внутренний инстанс агентства (отдельная база — данные наших клиентов физически изолированы) и публичный (поднимается в день выхода на рынок). Копий и форков не существует: различие «для себя / для массы» — это конфигурация и фиче-флаги, не отдельный код. Запуск SaaS = включение биллинга и регистрации, не переделка.
Продукт рождается пустым. Бизнес-логика нашего агентства (аудит, цены, скрипты, воронки) в код не зашивается. При создании команды — чистое пространство и мастер настройки. Всё «наше» — данные первой команды, введённые через интерфейс. Менять процесс = менять настройки, никогда не код.
Разработки не на критическом пути запуска компании. Запуск продаж едет на готовом стеке (документ 6). Исключение — сайт: он на критическом пути рекламы. Приоритет работ: сайт → Convloo (волнами) → Agency OS.

Прототип-предок: Zoned (ТЗ productivity-приложения). Отдельным продуктом не является; из него переиспользуются: механика таймер-сессий, привязка Telegram одноразовым кодом (TTL 10 минут), каркас API-роута ИИ-анализа задачи, принцип «ИИ оценивает сложность и длительность при создании», правило «интерфейс на одном языке, i18n-переводы в конце (но строки не хардкодим)».

2 · Agency OS — операционная платформа

Трекер задач + CRM-слой клиентов + движок планирования + AI-хаб. Заменяет ClickUp и становится операционным ядром агентства; горизонт — SaaS «операционка агентства под ключ». Статус: спецификация утверждена, разработка не начата.

2.1 Функции — 10 блоков

БлокСодержание
1 · Структура и доступПрофиль → компания → отделы → роли (администрирует/исполняет). Мультитенантность (tenant_id + RLS). Рабочие часы и выходные каждого. Ролевая видимость денег: исполнитель — без сумм, руководитель — бюджет своей зоны, владелец — всё, включая ставки часа. Офбординг «передать всё» одной кнопкой. Неизменяемый журнал действий.
2 · ЗадачиТри уровня таск-менеджеров: личный у сотрудника / сводный у руководителя / общий у владельца; раскидывание сверху с дублированием, галочки всплывают вверх мгновенно. Двухуровневое закрытие: «сделано исполнителем» ≠ «сдано отделом» (обязательный чек-лист сдачи из документа 11). Комментарии, вложения, упоминания в задаче. Глобальный поиск и фильтры.
3 · Каталог услугЗаполняется до старта: услуги → типовые подзадачи → шаблонные цепочки зависимостей → нормативные длительности. Стартовое наполнение — 104 микро-задачи документа 2. Кастомные задачи вне шаблонов.
4 · Карточка клиентаОтдельная CRM-база: заказ, услуги, дедлайны, срок договора, светофор. Денежные поля гибкие, дополняемые, с ролевой видимостью. Изменения в карточке доразбрасываются в трекер. Архив клиента с историей (не удаление).
5 · Движок планированияГенерация дерева задач из карточки. ИИ-оценка при создании: подзадачи + сложность + длительность; самокалибровка по факту тайм-трекинга. Раскладка по календарю с учётом загрузки и приоритетов. Умный перенос при срыве: ближайшее подходящее окно, опоздания видны руководителю.
6 · Зависимости и плавающие задачиШаблонные + кастомные зависимости. Тип «ожидание материалов» со списком (список = очередь операционки на дожим, документ 10). Плавающая задача: уникальный цвет, ближайшее допустимое окно без фиксации, вытесняется реальными, дрейфует; отметка «получено» активирует цепочку. Время ожидания логируется отдельно — разграничение вины по срокам (документ 2).
7 · Черновик → внедритьТекстом: клиент, сумма, задачи → ИИ даёт плоский список → метки исполнителей → «внедрить» → раскидано по отделу.
8 · Время и контрольТайм-трекинг сессиями (старт/пауза/финиш). Эскалация: Telegram исполнителю → руководителю. Повторяющиеся задачи ведения от срока договора. Индикатор загрузки (часы задач против рабочих часов); сигнал «отдел у предела N недель → триггер найма» — автоматизация триггеров документа 3.
9 · Аналитика владельцаЧасы × деньги: реальная стоимость услуги, эффективность людей, маржа (часы × ставка против цены), экспорт CSV. Второй контур сверки денег рядом с реестром начислений (документ 4).
10 · ИИ-хабМозг платформы: агент видит события трекера, следит за исполнением, советует, разбивает задачи. Снаружи — Telegram-личности по ролям (инструктор для всех + слой отдела + слой руководителя), одна память, слои доступа. Отвечает только из базы знаний со ссылкой; конфиденциальное (документ 5, личные условия) физически не загружается. Геймификация — выключаемый флаг компании: поля сложности/XP пишутся всегда, включение — поверх накопленных данных.

2.2 Архитектура ИИ-хаба

Хаб — изолированный модуль внутри Agency OS с тремя жёсткими правилами: один вход (вся платформа говорит с мозгом через единый внутренний интерфейс), своя память (отдельные таблицы: события, персоны, память), никаких прямых обращений к базе платформы (данные — через API с правами спросившего). Вынос в отдельный сервис — по триггеру «второй потребитель» (подключение Convloo к единой памяти или SaaS-масштаб); тогда модуль поднимается отдельно, вызов меняется на HTTP с тем же контрактом. Henry в Convloo живёт своим мозгом до этого момента; события Convloo идут в общую ленту через коннектор.

2.3 Безопасность

  • Фронт скрывает, база запрещает: Row-Level Security на каждой таблице; роль и tenant проверяются в базе, не в интерфейсе. Автотесты изоляции тенантов в каждом релизе.
  • Supabase Auth, 2FA обязательна владельцу и руководителям; офбординг = мгновенный revoke сессий и Telegram-привязки.
  • Ключи только в env серверов; сервисный ключ (в обход RLS) — только фоновым воркерам.
  • ИИ и бот ходят в данные от имени спросившего через его RLS-права — prompt-инъекция упирается в ту же стену, что и пользователь.
  • TLS, шифрование при хранении, ежедневные бэкапы + point-in-time recovery; вложения — по подписанным ссылкам с истечением.
  • Журнал действий неизменяем даже для владельца; Sentry без персональных данных; аудит зависимостей в CI.
  • SaaS-фаза: удаление аккаунта со стиранием, экспорт данных компании.

3 · Convloo — платформа отдела продаж

B2B lead-gen + CRM для агентств: поиск базы, обогащение и скоринг, прозвон и письма, ИИ-ассистент. Стек: Python FastAPI + Postgres/Alembic + Redis/arq (Railway) и Next.js (Vercel). Правило общего TS-стека на Convloo не распространяется — продукт уже живёт на своём. Позиционирование SaaS: ядро — агентства (B2B), расширение потом. Наш отдел продаж — первый клиент и полигон; Convloo не на критическом пути запуска компании.

3.1 Что уже есть в коде сверено с репо

Поиск (Google Places, Yelp, Foursquare, вакансии Adzuna, госреестр Британии), обогащение сайта/соцсетей/отзывов, ИИ-скоринг и драфты писем, полный CRM (статусы, заметки, кастом-поля, задачи, таймлайн), Henry (память, подтверждаемые действия), входящие с ИИ-классификацией ответов и авто-маршрутизацией, прогрев почты 20→200/день, suppression + one-click отписка, шаблоны и секвенции, команды с ролями, white-label отчёты, Stripe-инфраструктура (выключена), GDPR-экспорт/стирание, Telegram-бот, i18n en/uk/ru, экспорт Excel/CSV. Внутри репо — рабочие документы: ROADMAP (статусы, сверенные с кодом), CLAUDE.md (архитектура), AUDIT.

3.2 Ключевые решения по продукту

  • Воронка — центральная сущность. Лид всегда идёт по воронке команды; она задаёт путь касаний, скрипты, шаблоны писем и целевое действие — свободные поля: название (любой текст), цена (необязательно), действие при достижении (оплата+календарь / счёт / бронь / ничего). Зелёная кнопка селза рендерится из настройки воронки. Команда держит сколько угодно воронок; пакеты лидов распределяются в воронку. Пустой старт: никаких пресетов агентства в коде.
  • Режим прозвона — рабочее место селза. Конвейер: очередь (перезвоны → горячие → остальные) → карточка лида (выжимка, заход от ИИ, вкладки: полный анализ / отзывы / сайт / госданные / история) → звонок в один клик → исход одной кнопкой → следующий. Три состояния экрана: до / во время (таймер, REC, заметка в фокусе, исходы неактивны) / после (исход порождает следующее касание: письмо-догрев уже в черновике, чипы перезвона). Недозвоны: 3 попытки в разные дни, затем пауза.
  • Телефония — полноценная, с записью. Статистика по селзу (наборы, дозвоны, длительность, конверсия), запись каждого звонка с учётом правил согласия по штатам; следующий шаг — ИИ-разбор записей по скрипту (машина коучинга). Авто-набор — в план.
  • Три панели по ролям: «Добыча» (парсинг — менеджер+), «База» (вся база, фильтры, распределение пакетами/поштучно — менеджер+), «Работа» (селз: только его список и инструменты). Роли: Владелец → Админ → Менеджер → Селз; полный набор управления командой; удаление селза = обязательная передача лидов.
  • Языковой фильтр бизнеса — общий движок «язык бизнеса» (сигналы: язык сайта и отзывов, имена владельцев, соцсети, ключевые слова), у нас включён пресет RU+UA с раздельными метками; для рынка — «этнический таргетинг» любого языка, фичи такой нет у конкурентов.
  • Госреестры владельцев — единый формат коллектора (владелец, дата регистрации, статус, адрес); подключаются вслед за рынками: Британия есть, Флорида 1-я очередь, Украина (ЕДР) 2-я, Канада 3-я, Европа по странам 4-я; OpenCorporates — после расчёта экономики. Ограничение честно: часть штатов США анонимна (~треть лидов без владельца) — реестр шестой сигнал, не единственный.
  • События в общую ленту (для хаба, только требующие действия): горячий ответ → селзу мгновенно с черновиком; цель достигнута → руководителю + сделка; просроченный перезвон → эскалация; вечерняя сводка отдела руководителю, утренняя владельцу; пакет назначен → селзу; потолок затрат 80% → владельцу.
  • Экономика единицы: учёт затрат — в первую волну (каждый поиск/обогащение пишет стоимость; месячный потолок в долларах: 80% — предупреждение, 100% — стоп); себестоимость лида считается по коду; тарифная сетка — решение основателя при выходе на рынок, но 8 разных названий тарифов в коде сводятся к одной сетке заранее.

3.3 Интерфейс — 18 экранов, эталон утверждён

Холст макетов: Convloo — платформа. Иерархия: селз 8 экранов (Прозвон ×3 состояния, Главная, Письма, Входящие, Профиль, Помощь) → менеджер +6 (Главная отдела, База, Добыча, Воронки, Аналитика, Команда) → админ +2 (Настройки·Интеграции, Журнал действий) → владелец +2 (Главная компании с юнит-экономикой, Биллинг). Стиль: тёплый светлый #FAFAF7, акцент зелёный #1E6B4F, Manrope; семантика: жёлтый #9A6B12 — внимание, красный #A84632 — проблема.

Правила интерфейса: один экран — одно главное действие; показывать минимум, остальное по клику; роль определяет экран (пустых запретов нет — недоступное не показывается); один набор компонентов и один язык цвета; пустой экран учит; скорость — часть простоты. Текст: однострочное не переносится (обрезается многоточием), многострочное переносится аккуратно. Незавершённые функции на макетах помечены «скоро».

3.4 План доработки

Канон — 5 волн из ROADMAP репозитория (фундамент → ядро/Henry-агент → умные движки → рост → деньги и безопасность). Наши приоритеты волны 1 под собственный отдел: режим прозвона + телефония с записью; Connector QA (живость источников); языковой фильтр RU/UA; учёт затрат (cost cap); spam pre-flight; дневной дайджест и Telegram-алерты горячих лидов; починка команд и ролей; дизайн-система по эталону (замена ~900 inline-стилей).

3.5 Пересборка на компанию

Старые деплои (на личных почтах) пересобираются заново: поднять новые проекты Railway + Vercel на аккаунтах компании → переменные по .env.example (не по памяти) → все ключи перевыпустить от компании, старые отозвать → база с нуля (данные тестовые), полезные конфиги вытащить до удаления → прогнать happy-path → переключить домен → старое погасить и удалить. Трансфер проектов не используется — чистый передеплой. До деплоя решить вопрос названия продукта (Convloo/Convioo — финальное имя и домен).

4 · Сайт seventy-times.com

Next.js 15, статическая сборка, четыре языка, Vanessa (ИИ-чат на Claude с захватом лида), многошаговая форма, доставка лидов в Telegram + Notion + почту, страницы услуг и кейсов, сравнение, SEO/PWA. Решение: платформу не сносим — переработке подлежит контентный слой. Сайт — единственная разработка на критическом пути запуска (реклама ведёт на него).

4.1 Главный принцип: сайт не предрешает воронку

Готовится A/B-тест входа (реклама и селзы поведут и на аудит, и на брифинг), поэтому главная — нейтральная витрина без цен вообще: CTA «Обсудить проект» + «Как мы работаем». Офферы живут на отдельных посадочных вне навигации: /go/audit (аудит $100) и /go/brief (бесплатный разбор) — своя аналитика у каждой, офферные значения (цены, заголовки вариантов) — в одном конфиг-файле, меняются без раскопок кода.

4.3 Мобильная диета

Десктоп остаётся полным (пара фиксов по визуальному проходу). На телефоне: hero короче, кейсы — горизонтальная лента из 3, сравнение — аккордеон, ROI-симулятор свёрнут до кнопки, FAQ — 5 вопросов. Урезание — условным рендером, не удалением контента.

4.4 Без админки

Классическая админка не строится: сайт статический, контент — файлы данных (кейсы, услуги, команда, строки трёх языков); правка = изменение файла → автодеплой Vercel за минуту. Заявки уже падают в Telegram + Notion + почту — Notion и есть их база. Исключение — конфиг офферов посадочных (см. 4.1). Когда заработает Agency OS, сайт сможет тянуть кейсы из него — «редактирование без кода» появится оттуда.

4.5 Передеплой и порядок работ

Как у Convloo: новый проект Vercel на компании → env по .env.example → новые ключи (Anthropic, Resend, Notion, Telegram) → проверка → переключение DNS → удаление старого. Порядок работ по сайту: переработка контент-файлов → визуальный проход владельца посекционно (оставить/поправить/выкинуть) → мобильная диета → каркасы посадочных → офферные тексты при запуске рекламы → фото команды и данные автоковриков по готовности.

5 · Стыки и сквозные правила

  • Коннекторы продуктов: сайт → лиды в отдел продаж (сейчас Telegram/Notion, затем в Convloo); Convloo → достижение цели воронки создаёт карточку клиента в Agency OS (волна интеграций); события обоих продуктов → общая лента → хаб будит нужного человека в Telegram.
  • Единый ИИ: сейчас — единая память (общая событийная лента), не единый сервис; вынос мозга в отдельный сервис — по триггеру второго потребителя (раздел 2.2).
  • Цифры аудита: клиенту — $100 (на посадочной /go/audit и в воронках); $50 — внутренняя выплата селзу за проведённый аудит (документ 4). В интерфейсах клиента $50 не существует.
  • Стайлгайд интерфейсов Convloo (раздел 3.3) — эталон и для будущих экранов; Agency OS получит свой проход тем же методом (варианты → выбор → эталон).
  • Правки макетов и документов — republish той же страницы по её URL; копии на скачивание — с UTF-8-обёрткой.
