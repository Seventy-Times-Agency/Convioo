# Convioo — передача контекста, 22.09.2026

Документ для новой сессии. Здесь: что уже сделано и проверено, что
осталось, где грабли. **Секретов тут нет** — только имена переменных.
Значения смотреть в Railway.

## 1. Что это за продукт

B2B лид-генерация плюс CRM отдела продаж. Сейчас это **внутренний
инструмент собственной команды**, не продукт для клиентов: подписки
убраны (`BILLING_ENFORCED=false`), маржа и упаковка на рынок — позже.

Цикл: парсинг компаний → скоринг ИИ → распределение по продажникам →
звонки → расшифровка и разбор разговора ИИ → воронки.

**Жёсткие ограничения:** рынок Украина / ЕС / США / UK. Никаких
российских сервисов. Без эмодзи в коде.

Привязан 20.09.2026. Основной — апекс `https://convioo.com`,
`www` делает 307 на него. DNS **в GoDaddy** (`ns31/ns32.domaincontrol.com`).

## 3. Ключи: что подключено и как проверено

Все проверены живыми запросами, не «прописал и надеюсь».

| Переменная | Сервис | Чем проверено |
|---|---|---|
| `ANTHROPIC_API_KEY` | оба | разбор звонка вернул итог, следующий шаг, оценку |
| `GOOGLE_PLACES_API_KEY` | оба | поиск и детали работают; **отзывы пустые** — ограничение SKU |
| `ELEVENLABS_API_KEY` | оба | тестовое аудио распознано дословно, 11 слов с таймингами |
| `HUNTER_API_KEY` | оба | `/v2/account` + `/v2/email-finder` вернули почту |
| `RESEND_API_KEY` | оба | отправка через наш `send_email`, не через curl |
| `RINGOSTAT_AUTH_KEY` | оба | `sipstatus/online` и `calls/list` вернули 200 |
| `TELEPHONY_ROUTES` | оба | `380:ringostat` |
| `TELEPHONY_PROVIDER` | оба | **намеренно пуст**, см. ниже |
| `TELEPHONY_WEBHOOK_TOKEN` | api | вебхук отвечает 403 на чужой токен |
| `EMAIL_FROM` | оба | `Convioo <hello@convioo.com>` |
| `PUBLIC_APP_URL` | оба | `https://convioo.com` |
| `WEB_CORS_ORIGINS` | api | апекс + www + `convioo-zeta.vercel.app` |
| `AUTH_JWT_SECRET`, `FERNET_KEY` | оба | заданы |
| `DEMO_MODE` | оба | **`1`, см. раздел рисков** |

**Про `TELEPHONY_PROVIDER`.** Пуст сознательно. `get_provider_for`
сначала ищет префикс в `TELEPHONY_ROUTES`, а если не нашёл — берёт
`TELEPHONY_PROVIDER` как провайдера **по умолчанию для всех остальных
номеров**. Когда там стоял `ringostat`, американский `+1` уехал бы
звонить через украинского оператора по международному тарифу. Сейчас
маршруты работают, остальные страны возвращают «звонок невозможен».
При добавлении Twilio под США — дописать в `TELEPHONY_ROUTES`,
а не возвращать значение по умолчанию.

### Ключи, которых ещё нет

Всё работает без них, они расширяют охват:
`APOLLO_API_KEY`, `COMPANIES_HOUSE_API_KEY`, `OPENCORPORATES_API_KEY`,
`YELP_API_KEY`, `FSQ_API_KEY`, `ADZUNA_*`, `PAGESPEED_API_KEY`,
`SENTRY_DSN`, Opendatabot (украинский ЄДР, нужна платная подписка).

Лимиты бесплатных планов: Hunter 50 поисков + 100 верификаций в месяц,
сброс 20 числа. Resend 3000 писем в месяц.

## 4. Телефония — состояние

Готово всё, кроме номера.

- Ключ API работает **в пробном периоде, без выбранного тарифа**.
- Проект в Ringostat: `seventy-times.com`, **Project id `247726`**.
- Часовой пояс проекта — `Europe/Bucharest` (Киева в списке нет,
  Бухарест совпадает с ним круглый год; Варшаву брать нельзя, час разницы).
- Настройки вызовов: целевая длительность 60, цикл продаж 30,
  период поиска ответственного 30.
- Предупреждение о записи разговора **включено** — юридическое требование.
- Вебхук заведён в разделе **Webhooks 2.0**, событие «После звонка», POST,
  `Content-Type: application/json`, добавлены все параметры.

**Имена полей в Webhooks 2.0 отличаются** от классических вебхуков.
`parse_event` в `core/services/telephony/ringostat.py` теперь понимает
оба набора через `_first()`:

| Классика | Webhooks 2.0 |
|---|---|
| `call_id` | `cdr_id`, `uniqueid` |
| `callee` | `dst` |
| `caller` | `userfield` |
| `status` | `disposition` |
| `call_duration` | `duration` |
| `dialog` | `billsec` |
| `recording_wav` | совпадает |

Ссылка на запись приходит прямо в вебхуке — дёргать `/calls/list` не нужно.

**Чего не хватает:** виртуального номера `+380` и SIP-аккаунтов.
`sipstatus/online` возвращает пустой список. Баланс €4.36 (их бонус).

**Что спросить у менеджера Ringostat:**
1. Мобильный номер или только городской, цена номера в месяц.
2. Цена минуты на украинские мобильные.
3. Дают ли номер в пробном периоде.
4. Сколько одновременных исходящих на одном номере.
5. Запись в два канала (стерео) — нам нужно для точного деления реплик.
6. Принимает ли `extension` в `callback/outward_call` обычный мобильный
   вместо SIP — от этого зависит, можно ли тестировать без их приложения.

**Как устроена привязка продажника.** Автоматической выдачи нет и быть
не может: в API Ringostat нет метода создания сотрудника или SIP-аккаунта.
Порядок ручной: завести сотрудника в кабинете Ringostat → скопировать его
внутренний номер → вписать в Convioo, Настройки → Телефония. Пока поле
пусто, кнопка «Позвонить» отдаёт 409 с подсказкой. У каждого свой
extension, номер общий — иначе разбор звонка прилетит не тому человеку.

## 5. Что сделано в этой сессии

**Домен.** Привязан `convioo.com`, апекс сделан основным, `www` редиректит.
NS возвращены из Vercel в GoDaddy. `PUBLIC_APP_URL` и `WEB_CORS_ORIGINS`
переведены на домен в обоих сервисах; в `workeer` переменной не было
вообще — он минтил ссылки на `localhost:3000`.

**Почта.** Resend подключён, домен подтверждён, DKIM + SPF + MX + DMARC
в зоне. Проверено отправкой через `email_sender.send_email`. Важно:
эта функция при отсутствии ключа **не падает, а пишет письмо в лог и
возвращает `True`** — по одному `True` судить нельзя.

**ЛПР.** Добавлен шаг Hunter в каскад `find_decision_maker`:
`domain-search` с `decision_maker=true` отдаёт имя, должность и
проверенную почту за один кредит и работает, когда имени ЛПР мы ещё
не знаем (прежний `email-finder` требовал знать имя заранее).

Перед платным запросом спрашивается бесплатный `email-count` — если у
домена нет личных почт и руководства в индексе, кредит не тратится.
На прогоне по четырём доменам списался **один кредит из четырёх**.
Это ответ на вопрос «а если ищем по региону без клиентов» — там ноль.

В каскаде Hunter стоит между реестрами и Apollo.

**Исправлено попутно:** `_DM_WORDS` содержал `ceo`, но не
`chief executive` — строка `Chief Executive Officer` подстроки `ceo`
не содержит, и развёрнуто написанный CEO не помечался как ЛПР.

**Вебхук телефонии.** Брал провайдера из `TELEPHONY_PROVIDER`, а не из
адреса, — после очистки той переменной начал молча отбрасывать все
события с `provider disabled`, отвечая при этом 200. Теперь резолвит по
имени из URL. Плюс разбор имён Webhooks 2.0 (см. выше).

Коммиты: `9faf6e9`, `7b12e0f`. Оба выложены через `railway up`,
проверены на живом проде.

**Состояние тестов:** 668 проходят, 8 пропущены, ruff чист,
70 миграций alembic.

## 6. Риски и незакрытое

**Демо-вход открыт на боевом домене.** `DEMO_MODE=1`, и
`POST /api/v1/auth/demo?role=owner` отдаёт сессию **владельца** без
пароля, в **боевой базе** — `ensure_demo_data` сеет туда демо-команду.
Любой, кто откроет `convioo.com`, может зайти хозяином. Владелец знает
и отложил осознанно.

Договорённость: сделать **отдельный контур**. `DEMO_MODE` — флаг
процесса (`config.py`), влияет на весь бэкенд сразу (вход, парсер,
обогащение, лимиты), поэтому «демо и прод в одном сервисе» невозможно.
План: второе окружение `demo` в Railway со своими Postgres/Redis и
`DEMO_MODE=1`, ветка `demo` в Vercel на поддомен `demo.convioo.com`.
Стоит второй пары Postgres+Redis. После этого `DEMO_MODE=0` на проде.

**Регион Resend — North Virginia (us-east-1), не EU.** Для рассылки по
Украине и Европе письма ходят через США. Смена региона = удалить домен
и завести заново с повтором DNS. Не срочно, но знать стоит.

**Google Places: отзывы приходят пустыми.** Проверено на двух местах,
включая Google Sydney. Диагноз — ограничение SKU/пробного аккаунта,
не наш код.

**Sentry не настроен.** `sentry.*.config.ts` в репозитории есть, DSN нет
(потерян вместе со старым проектом). Нужен — заводить новый проект.
