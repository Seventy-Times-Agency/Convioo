# Convloo — первый запуск без переменных

Первая версия запускается **без единой переменной окружения** и сразу
в демо-режиме: база — локальный SQLite-файл, схема создаётся сама,
верификация почты выключена, а парсер отдаёт муляж — чтобы можно было
прокликать каждую кнопку. Ничего из функций не вырезано — весь код на
месте, переменные добавляются при хостинге.

## Запуск (2 терминала)

```bash
# 1. Бэкенд (Python 3.12)
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python -m leadgen                      # API на :8080, БД — ./convloo.db

# 2. Фронтенд
cd frontend && npm install && npm run dev   # :3000, сам проксирует на :8080
```

Открыть http://localhost:3000/login → блок **«Демо-версия — без
регистрации»** → выбрать роль. Всё создастся при первом входе.

## Что можно потыкать в демо

| Роль          | Что открыто                                              |
|---------------|----------------------------------------------------------|
| **Селз**      | Работа: очередь (перезвоны → горячие → остальные), карточка с заходом, click-to-call, три состояния звонка, исход одной кнопкой, зелёная кнопка из воронки; Входящие; Письма |
| **Менеджер**  | + База с фильтрами (в т.ч. RU+UA) и распределением «выбор → селз → воронка → назначить», Добыча (муляж парсера), Воронки (конструктор), Аналитика, Команда |
| **Админ**     | + Настройки: потолок затрат, интеграции, статусы; Журнал действий |
| **Владелец**  | + Биллинг, передача владения, изменение потолка           |

**Добыча в демо**: вводишь любую нишу и регион → «Найти и оценить» →
за секунды приходит 20–50 фиктивных компаний с рейтингами, отзывами,
скорингом, выжимкой, заходом, метками языка RU/UA и частью без сайта.
Дальше их можно фильтровать, раздавать в воронку и звонить — весь
конвейер настоящий, ненастоящие только данные.

Что работает без ключей по эвристике (не заглушка, а встроенный
фолбэк продукта): черновики писем, Henry, спам-проверка, учёт затрат
(в демо стоимость тоже пишется — потолок и предупреждение на 80%
проверяемы).

Обычная регистрация тоже работает — почта в демо подтверждается сама.
Новая команда стартует пустой, с мастером первой воронки.

Пароль демо-аккаунтов, если нужен вход по форме: `demo1234`
(`owner@` / `admin@` / `manager@` / `sales@demo.local`).
Тот же набор можно засеять командой `python -m leadgen.scripts.seed_demo`.

## Как выключить демо

Демо включается автоматически, когда база SQLite **и** нет
`GOOGLE_PLACES_API_KEY`. На хостинге с настоящими ключами оно
выключится само: кнопки демо-входа не будет, вернётся верификация
почты, парсер пойдёт в реальные API. Принудительно: `DEMO_MODE=0`
(выкл) или `DEMO_MODE=1` (вкл).

## Что оживёт после добавления переменных (при хостинге)

Полный список — `.env.example`. Ключевые:

| Переменная | Что включает |
|---|---|
| `DATABASE_URL` | Postgres вместо SQLite (прод; alembic сам накатит схему) — вместе с ключом Google выключает демо |
| `AUTH_JWT_SECRET`, `FERNET_KEY` | боевые секреты сессий и OAuth-хранилища |
| `GOOGLE_PLACES_API_KEY` | реальный поиск лидов (Добыча) |
| `ANTHROPIC_API_KEY` | скоринг, выжимки, заходы, Henry, разбор ответов |
| `REDIS_URL` | воркер arq: авто-письма воронок, дайджесты, эскалации |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_WEBHOOK_SECRET` | уведомления событий |
| `YELP_API_KEY`, `FSQ_API_KEY`, `ADZUNA_*` | дополнительные источники |
| `RESEND_API_KEY` / Gmail/Outlook OAuth | реальная отправка почты |
| `NEXT_PUBLIC_API_URL` | адрес API для фронта на отдельном домене |

Проверка живости источников после выдачи ключей:
`RUN_LIVE_SMOKE=1 pytest tests/test_connectors_smoke_live.py -v`
